# VIS-footout：伸进过道的脚（坐姿、无主的椅子、陈默的腿）

- 先查骨架，再看贴图：人物姿势写成「髋、膝、踝」三个点时，单元测试要量骨长（和 `LegForest.BODY` 比，±5%）和膝盖相对髋—踝连线的位置（不能在连线下方，即不反折）。以前 footOut 为了满足「车道上方不高于碰撞上沿 + 5 cm」，把膝盖压到离地 0.14 m，腿反折约 40°；没有上身时看不出来，补上上身轮廓后就成了「坐着的人腿瘫在地上被拖着」。
- 先算几何能不能同时满足验收线，再定姿势。从 0.44 m 的椅面伸直的腿，车道中心约 0.27 m 高、车道近端约 0.45 m，碰撞盒（0.16 m）不能改时一定违反 WP6 验收 4（线框与模型边缘 ≤ 5 cm）。验收线只认 DESIGN §10 的书面豁免，工作包不能靠缩小测试的取样范围绕过去（第一版这么做了，被评审打回）。改成「坐在车道外沿的地上、两手撑地、腿伸直平放」：骨架正常，整条腿贴着碰撞上沿，原来的顶边测试一行不用改，也顺带去掉了过道当中、人群当中孤零零的椅子。
- 坐在地上的人，上身后仰受外沿 0.86 m 限制（髋在 0.675，背和头在 0.79 左右），只能仰约 4.5°；靠两臂斜着撑到髋外侧的地面上读成「随便坐着」。撑地的手要有「伸出时最低点在地面 ±2 cm」的测试，后仰会把手抬起来。
- 注释里的性能说法要对照代码核实：InstPool 只有调了 `trackVariantRanges()` 才按变体裁 drawRange（现在只有 LegForest 的池子调），ArchetypePoolImpl 的每个实例都处理整个合并几何体。所以原型的变体越多、每个实例越贵；footOut 每人两个实例都要用，就只留两个变体（腿 120 + 上身 70 = 190 个三角形，每人 380，比原来的 572 少）。用临时 vitest 把 `variantTriangles` 写到 scratchpad 量。
- 收腿时不要整个人绕髋转：外沿 ≤ 0.86 m 的约束对每一个伸缩进度都要成立。腿单独一个变体绕髋转，上身另一个变体只扭 0.3 rad 并坐直。测试直接用导出的 `footBodyMatrix` / `footLegMatrix` 扫 e ∈ [0, 1]，和 `place()` 共用同一份矩阵代码。
- `GeoBuilder.segment` 用最短旋转对齐，斜放的长方体截面会绕长轴歪，顶面的粉笔条随之倾斜。需要「高」始终朝上时自己 `makeBasis`（`footOut.ts` 的 `limb`）。
- 陈默留在过道里的腿：`LegForest` 的目标腿是一根按髋—踝距离缩放的直腿（上限 1.25），目标点离髋太远就是僵直的侧踢。脚踝放在碰撞盒里靠他的一侧，等他让到 65% 再伸出去，髋降 2.5 cm、支撑腿微屈（`cos(hip) = (STAND_HIP − drop − ankle) / 腿长`，脚仍着地）。`boundary.test` 要求让开后髋高 > STAND_HIP − 0.05，降幅不能超过 5 cm。
- 在单元测试里按帧量人的位置时，要排除越过之后缩小消失（U6 的 `applyFade`）的那几帧：矩阵的 `getMaxScaleOnAxis() < 1`。
- 截「撑跃越过某个障碍」：perfect 自动驾驶常常侧步绕开中道的 low，截不到。在页面里逐 tick `step(1)`，等 `mode === 'air'` 且同车道的这个障碍 `ds` 在 ±0.3 m 内再 `render()`；绕开时改用 `setAutopilot('off')` + `setInvincible(true)`，在 `ds ≈ 1 m` 时 `input('up')`。
