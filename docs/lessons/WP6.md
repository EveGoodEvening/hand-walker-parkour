# WP6 Lessons

只追加（OWNERS.json APPEND）。记录可复用的经验：库版本、踩过的坑、被纠正的做法。lead 集成时汇总到 AGENTS.md。


- 「每个原型只有一个 InstancedMesh」但一个原型要画好几种障碍：几何体里并排放每种障碍的变体，顶点属性 `aHw.x` = 变体号（−1 = 共用），实例属性 `iHw.x` = 要显示的变体，顶点着色器把不属于本实例变体的顶点收拢到一点（`transformed = vec3(0.)`，三角形退化不光栅化）。代价：每个实例都要处理全部变体的顶点，`renderer.info.render.triangles` 也按全量计数——变体要做得省（人物部件尽量一个盒子），重的特殊变体会让每个实例都背上。
- 同一套补丁顺便做了「着色遮罩」和逐顶点自发光：r186 的 `color_vertex` 里是 `vColor.rgb *= instanceColor.rgb;`，把这一行换成 `mix(vec3(1.0), instanceColor.rgb, aHw.z)`，鞋底、手、粉笔白线就不会被衣服颜色染色；自发光（周主任的烟头、电子栏杆红灯）在 `emissivemap_fragment` 之后加进 `totalEmissiveRadiance`。单元测试断言这一行还在，three 升级改了它会立刻报错。
- 在 WP3 的 LampField 补丁上叠自己的补丁：保存原来的 `onBeforeCompile` 并先调用它，再改自己的片段；`customProgramCacheKey` 也要串接（原型方法默认返回 `onBeforeCompile.toString()`）。只改 LampField 不碰的片段（color_pars_vertex / color_vertex / begin_vertex / color_pars_fragment / emissivemap_fragment）。
- 贴花要逐顶点透明度：把 `color` 属性做成 itemSize 4，three 会定义 `USE_COLOR_ALPHA`，Basic 材质开 `vertexColors` + `transparent` 即可让边缘淡出。
- test 模式下 `shot.mjs` 只在最后渲染一帧（中间的 `step` 不渲染），所以 NPC 的一切画面状态都必须是时间的纯函数：伸脚按段内时间；「玩家进入 3 m」的凝视按当前距离 ÷ 速度倒推触发时刻；受击、让一下、crowd cue 按事件时刻（事件每 tick 都会分发给 View）。不要靠「第一次看到的那一帧」。
- 画面的 tSeg 要和 Sim 碰撞用的 pace.tSeg 一致：段首是 `segment` 事件那一 tick 的 `snap.t`；读章 / 跳转 / 重来后 `onReset` 里用 `snap.t − seg.timeAt(snap.segBeat)`（Sim 跳转时把 tSeg 设成 timeAt(beat)）。onReset 在事件分发之后调用，会覆盖 segment 事件里设的值。
- 单元测试里比较两次运行的逐 tick 序列时，不要用 CORE Driver 的 `tap()`：它内部多走一个 tick，两次运行的时钟就错开了；用 `press()` + `release()` 只排队输入。
- `easeInOutSine(0)` 返回 −0，`expect(x).toBe(0)` 会失败（Object.is）；返回值加 `+ 0` 归一。
- 「安静的一秒」的动画时钟：几次静止窗口重叠时要先合并，否则扣掉的时间会重复累计，时钟倒着走。
- 「模型边缘与碰撞盒偏差 ≤ 5 cm」的单元测试：整宽的盒子顶点都在两端，按顶点找「车道中线上方最低的面」会漏掉；要按三角形的 x 跨度判断（跨过 x = 0 的三角形里取最低）。地面暗带（y ≤ 0.005 的深缝影子）要排除。
- 碰撞盒是 85% 规则的外层盒；视觉 ≈ 碰撞 ÷ 0.85，但大障碍（整宽横档 1.65 m）按比例会外扩 29 cm，和「偏差 ≤ 5 cm」冲突。WP6 的做法：每面外扩 min(按比例, 5 cm)；横档下沿再往下 2 cm（看起来更低，只会让人更早伏低）。
- 人腿障碍的碰撞盒高 1.70 m，但 NPC 只建到腰带（§5.7）：线框顶面会比模型高 0.65 m。玩家盒最高 0.85 m，这部分不影响任何判定，是有意的差异。
- 占位主角正好挡住中道；截图画廊把障碍放在左右两道，并用 `npcStage(name, { ahead })` 把后面几排拉近。
- `renderer.info.memory.geometries` 在第一次跑某一章时会逐步增长（预建的 chunk 第一次被渲染才上传 GPU），跑完第一遍之后就平了（第一章 5 分钟：60 → 151 后不变）。WP6 自己的几何体（18 个原型池 + 8 个人物部件 + 2 个爬行者部件）都在 init 时一次建好。
- 热路径不要 `createRng()`（每次都 new 一个对象）：按 id 取固定随机数用 `sin` 散列，或读章时预先算好。
- 第二到五章的数据由 WP2 并行编写，WP6 截图时没有这些段落：`__game.ext.npcStage(name, { ahead, follow })`（只在 ?test=1 / ?debug= 下可用）用合成的障碍和人群在玩家前方搭场景，走和正式数据完全相同的放置代码；`npcCrowd(group, op)`、`npcAsk('part'|'ignore')`、`npcHit()` 模拟 crowd cue、「让一下」和人群段绊倒；`npcStats()` 返回人数、各类可见 InstancedMesh 数和本帧耗时。tests/visual/WP6.json 全部基于这些扩展。
- 实测（无头 Chrome，本机）：森林舞台高画质 64 人，ObstacleView 每帧 0.22 ms；梦里高画质 64 人 + 爬行者：人 6 个 InstancedMesh、爬行者 2 个。第一章低画质 e2e:perf 峰值 25 次 draw call、24.5k 三角形。
- （验收第 1 轮返工）「模型边缘与碰撞盒偏差 ≤ 5 cm」不能只测原型池：legs / crawler 由 LegForest / Crawlers 画，要按 ObstacleView 实际放出来的实例算世界包围盒（`tests/unit/npc/helpers.ts` 的 `stageView` + `instancedBounds`，按实例的变体过滤顶点，规则和顶点着色器相同）。横向、纵向只看 0.85 m 以下（玩家碰撞盒最高 0.85）。
- 人腿障碍的碰撞盒是 0.52 × 0.30 的横长方形，人的腿和胯只有 ±0.2 宽：给障碍里的人加垂在身侧的前臂（髋部件多一个实例，不加 draw call，外沿 ±0.28），每人站在车道中心（多车道人墙不要按 (x1−x0)/n 均分），再沿朝向后退 0.045 m 让鞋的前后沿居中。整个人侧身（±90°）时剪影只有 0.26 宽，比碰撞盒窄 13 cm（危险方向），所以脚只取朝前 / 朝后（±0.1 rad），「侧身」改成只扭上身 ±0.3；凝视时障碍里的人鞋尖最多转 35°、上身不跟着转。胯的下沿抬到 0.855 m，0.85 以下只剩腿、鞋和手。
- 路边的人不加手臂：走廊里路边那一条只有 0.48 m 宽（右道玩家盒外沿 1.32 到墙 1.8），人面朝 ±s 时加了手臂会穿墙。走廊缺省人群带改成 [1.54, 1.6]。
- 走路的人（walk 行为）沿 s 的外沿随步态在中心前后 0.06–0.48 m 之间摆（§5.7 规定的 ±22° 摆腿），碰撞盒 0.30 深取的是平均；横向仍在 ±5 cm 内。这是有意的例外，已写进契约申请。
- 陈默蹲着要收进 0.70 × 0.50 × 1.00 的盒子：深蹲（髋高 0.215、髋角 125°、膝角 140°、膝盖外分 0.45、上身前倾 0.4），整个人沿 −s 退 0.147 m，躯干比普通人短 10 cm，头顶 1.03 m，正好和镜头（0.92 m）一样高——「视线和我平齐」。参数是在 vitest 里网格搜出来的（CHEN_SQUAT 可写，探针改它再 `view.frame()` 重画）。
- 伸进过道的脚：碰撞盒里只能有低于 0.21 m 的东西（|x| ≤ 0.35），大腿从 0.46 m 的椅面落到 0.14 m 的膝盖要 0.3 m 横向距离，小腿还要横过整个车道，所以髋离碰撞盒中心至少 0.70 m（膝盖是铰链，髋、膝、踝的水平投影共线，斜着伸也省不下来）。中道的脚就让那个人侧身坐在两条车道之间的空当里（椅子外沿 0.86 < 相邻车道玩家盒 0.88），两条腿并排伸直横过车道，正好填满 0.30 的深度；路边 seatedRow 里坐在同一位置的人要去掉。
- 几何体镜像（负缩放 / 负行列式的 withMatrix）会翻转三角形绕向，背面剔除后看到的是内面；左右两侧的变体要么关于 z = 0 对称再绕 y 转 180°，要么用镜像后的坐标重新建盒子。
- `defs.ts` 用了 `import.meta.glob`，tsx 脚本里是 undefined：要跑整个 ObstacleView 的探针，写成临时的 vitest 文件（提交前删掉）。vitest 5 对通过的用例不打印 console.log，探针结果写到 scratchpad 的文件里。
- 调试舞台的路边走路的人以前按真实时间走，「安静的一秒」里会滑行；现在和正式数据一样按动画时钟。画面里任何「位置按时间走」的东西都要和腿的动画用同一个时钟：碰撞盒按段内时间走的行人用段内时间驱动步态，路边的人用动画时钟驱动位置和步态。
- 「减少闪烁」：`ctx.settings` 是 Game 持有的同一个对象，设置界面改了立即生效，每帧读 `ctx.settings.reducedFlicker` 即可；明灭的光源换成 0.5 Hz、最低 0.4 倍峰值的平滑明暗（behaviors.reducedPulse）。截图可用 `?rf=1`。
- 本机浏览器命令要经 `~/.claude/bin/heavy-gate -l <标签> -- <命令>` 并在后台运行（PreToolUse hook 会拦截），这和「不要后台」的任务说明冲突时按 hook 来；一次只开一个浏览器，依次跑。
- （验收第 2 轮返工）变体收拢（顶点着色器把不属于本实例的顶点收成一点）省 draw call，但**每个实例都要处理整个几何体**，renderer.info 也按全量计三角形。髋部件带着 8 个变体时每个实例 360 个三角形，低画质 24 人就有 10.3k，超过 §9.4 的 NPC 8k。做法：低画质用单独的小几何体——feet（鞋 + 合并的腿，同一个 InstancedMesh）、hipsLow（裤子 / 裙子 / 运动裤 / 垂着的手）、special（周主任、班长、陈默，只在他们出现时才有实例），仍然 ≤ 3 次 draw call；同时去掉永远看不见的面（鞋底和腿的上下面、腰带的底面）。实测第一章 1-1 低画质 24 人 5.1k。中、高画质不受 8k 约束，仍用一个全变体的髋部件（再拆会超出 5 / 6 次 draw call）。
- `PartBuilder.with({ alpha })` 是按三角形整体取值的；贴花外圈要淡出必须逐顶点（`triAlpha`）。外圈两个三角形分别取内、外两个值时，边缘是一圈交替的锯齿。
- 段内时间要按段记：每段在模拟时钟上的开始时刻（segment 事件 / onReset）。已经过去的段照常计时、拍号取 +∞（让开的陈默不会重新蹲下，人墙保持移动后的位置），否则跨过段界的那一帧路边的人、爬行的人、行人障碍全部跳回出生点（实测最大跳 31 m）；还没到的段时间 0、拍号 −1。失败（fall）以后模拟不再推进 tSeg，画面的障碍时间也要停在失败那一刻，retry 时由 onReset 重新同步。
- 「让到一边」这类画面位移要查相邻车道的障碍：1-2 的储物柜把中道夹在 ±0.65（视觉）之间，陈默默认让开 0.56 m 会半个身子钻进柜子。读章时按同一 s 附近相邻车道障碍的内沿（碰撞盒 − 5 cm − 2 cm 余量 − 身体半宽 0.33）限制让开的距离，两侧都有障碍时取空间大的一侧。
- 同一套场景里操作相反的两种障碍（田径场：L → hurdleDown 撑跃，H → hurdle 伏低）剪影必须一眼分开：low 的版本做成实心、贴地、下面没有缝（框架铺满整个宽度，条纹横板斜靠在上面，最高处整条粉笔白），bar 的版本下面是一道空的深缝。单元测试用从玩家一侧水平射来的光线检查「有没有缝」。调试舞台 `npcStage('track')` 把两种栏架并排放。
- 走路的人凝视时只转鞋尖、腿不跟着转：腿绕竖轴一转，±22° 的前后摆腿就变成横着摆（螃蟹步），靠墙走的人脚会踩进墙里（实测 2.05 > 1.8）。
