# WP5 Lessons

只追加（OWNERS.json APPEND）。记录可复用的经验：库版本、踩过的坑、被纠正的做法。lead 集成时汇总到 AGENTS.md。


- 姿态构建（`actors/handCycle.ts` 的 PoseBuilder）按拓扑序写局部旋转、同时维护 FK。改了父骨骼之后，子骨骼缓存的关节位置是旧的：做两骨 IK 之前必须先对上段骨骼 `fk()` 一次，否则 IK 从静止姿势的肩膀出发，手永远够不到目标（踩过：手腕停在目标前 9 cm、低 4 cm）。
- 无头测试的时间：`__game.step(n)` 之后只渲染一帧，按渲染 dt 推进的过渡（dt 还被截到 0.1 s）几乎不动，「上一帧的相机位置」也可能是很久以前的。WP5 的过渡、淡入淡出、计时一律按模拟时钟差推进（不截断）；弹簧类在间隔 > 0.25 s 时直接吸附；依赖相机的放置（侧墙镜替身沿 s 放在哪）用 §5.4 追尾机位的解析值，不读上一帧的相机。截图清单里在截图前加 `(()=>{for(let i=0;i<24;i++)__game.step(2,{render:true})})()`，模拟真实帧率下的最后 0.4 s。
- PoseHistory 按 tick 需要数据，但姿势只在渲染时算：两次渲染之间隔了多个 tick 时，主角按首尾快照线性插出中间各 tick 的爬行输入补写历史（纯函数 crawlPose，不动弹簧状态），否则 0.35 s 延迟的替身在无头测试里采到的是一帧很旧的姿势。
- 侧墙镜的「真实」倒影在玩家同一里程处，离追尾镜头的视线约 66°，根本看不见。替身不做真实反射：按墙面对称放进镜中房间，离玻璃的深度按玩家到墙的距离压缩（0.4–3.2 m），沿 s 放到镜头前方约 0.6 × 水平半视角处（三条车道都看得见，单元测试 + 截图）。端墙镜替身离玻璃 0.2 × 玩家到镜面的距离，横向压缩一半，保证在 1.9 m 宽的开口里。
- 脚本姿势（clip）自带根高度（站立 0.5 m、倒立 0.69 m）。放置替身时要把地面高度加上去，不能覆盖 root.y，否则站着的替身陷进地里一半。
- 平面影子：光线太陡（morning 的 planarDir 仰角约 58°）时爬姿只有 0.3–0.6 m 高的身体把影子全压在身下，追尾镜头看不见。投影前保证光线水平分量 ≥ 1.2 × 竖直分量（方向不变），影子才「永远落在前右方」。影子材质用 FrontSide：压扁的闭合网格朝上的面投下来是正面、朝下的面被剔除，没有模板时也只压暗一层；用 DoubleSide 时降级路径处处压暗两次。
- 像素检查（`__game.ext.wp5PixelCheck`）：渲染到带 stencilBuffer 的 WebGLRenderTarget，在同一个任务里 readRenderTargetPixels；渲染目标是线性色（没有色调映射）。测遮罩范围时要把透明叠加层也藏掉，否则叠加层混在标记色上，标记色被冲淡、数不出来。
- 在 WP3 的 LampField 补丁之上再改 Lambert 着色器（替身去饱和）要串联 onBeforeCompile，并串联 customProgramCacheKey（`${prev()}|wp5tint`），不能直接覆盖。
- CORE 占位 kit 的端墙镜「镜框」是一整块实心面，把开口挡住了（已写进 contract-requests/WP5.md）；1-6 的替身和「嘘」在占位世界里只能从镜中房间内部看（截图清单里有 inside 一张）。WP3 的走廊 kit 只要按 §5.8 留洞就没问题。
- 检查点在段中间时，重来不会重放检查点之前的段内事件：在检查点之前出现的替身（double cue）重来后就没了。写数据时替身的 double cue 放在检查点之后，或者在检查点之后再发一次。
- 静场里主角由 WP5 画：放在 `STILL_ORIGIN × StillSet.playerAnchor(variant)`，锚点约定为「主角骨盆正下方的地面，主角朝 −z」；各 set 不要自己画主角的身体（CORE 的占位 set 画了两只静态的鞋，会和主角重叠）。机位（shots.ts）也相对这个锚点。
- 调试扩展里读当前里程用 `__game.getState()`：`step(n)` 之后还没渲染时，ViewSystem 最后收到的快照是旧的。
- 单元测试：Float32 存的四元数 slerp 后用 `angleTo` 比较，acos 在 1 附近放大误差，约 5e-4 rad，阈值取 1e-3。
- 摔倒机位按 §5.4 的 (0.2, 0.18, +1.0) 会插进拖在身后的腿里（腿拖到根后方约 1.1 m，右脚正好在那儿），画面被一条裤腿占满。实现里横向让到腿外侧（x + 0.6），高度、距离、滚转照旧。
- three r186 的 `q.slerpQuaternions(qa, qb, t)` 是 `this.copy(qa).slerp(qb, t)`：`this === qb` 时 qb 先被覆盖，结果永远是 qa。原地混合要先 slerp 进临时四元数再 copy 回去（腿自主抬起曾因此完全不动）。单元测试不能只查「四元数有限、归一」，要查骨骼真的转了。
- 姿势的高度（伏低、腿自主抬起、摔倒）要移动根（骨盆关节）的高度，不能只改 `torsoTilt` 的髋高参数：那个参数只决定躯干倾角，骨盆还在静止高度 0.34 m。改高度的姿势一律用蒙皮后的网格量最高点 / 最低点做单元测试（伏低 < 最低横档下沿 0.36 m）。
- 追尾机位（0.92 m 高、身后 2.35 m）只比爬姿的背高约 11°：肩比髋高得越多，背在画面里越像一块竖着的板；地上的手永远投在髋的下方。「用手爬」的读法靠：躯干接近水平（肩只比髋高约 0.1 m）、两腿成 V 字拖在身后、摆动手的肘向外上方抬起、侧弯与髋滚转略大于 §5.6、行李腿左右甩。鞋底的位置用单元测试按追尾机位投影检查（在画面内、避开 HUD 节拍点）。
- 调 Node 里的姿势时，用一个软件光栅器（蒙皮顶点 → 追尾相机投影 → z-buffer → PNG）先迭代，比每次开无头浏览器快两个数量级，也不占浏览器槽位；最后再用真实截图确认。
- 调试用的反光面（水洼）不能放进活动候选列表：候选按距离排序，章首离玩家最近，会占掉真实水洼的名额并在玩家脚下画一块暗斑。只在调试接口被调用后才加入候选。
- 本机的无头浏览器必须经 `~/.claude/bin/heavy-gate -l '<label>' -- <命令>` 启动（PreToolUse hook 会拦截直接启动），并且用后台运行等待；同一时间只跑一个。

## 修复轮 U5（2026-10-01）

- 追尾机位挡障碍是几何问题，不是调参能解决的：机位在主角身后、比他的头高，「过头顶看到地面」的盲区长 = h·(back + 0.45)/(h − 0.68) − back。0.92 m / 2.35 m 时约 7 m，1.15 m / 2.8 m 时仍约 5 m，要压到 1 m 以内得把镜头抬到近 3 m。所以「本车道有必需障碍时上半身淡到 40%」（readability.ts）是必需的，不是可选项。遮挡测试（occlusion.test.ts）按同一套淡出规则判断，并且确认过：只抬机位、不淡出时 243 / 335 个障碍不合格。
- 一个 SkinnedMesh 里只淡一部分：刚性蒙皮下每个顶点只属于一根骨骼，顶点着色器里按 `skinIndex.x` 分组取 alpha（uniform vec4），片元里 alpha < 0.01 就 discard（不写深度，藏起来的部分不挡后面）。材质一直设 transparent（切换 transparent 会换着色器变体，第一次触发时卡一下），全为 1 时画面与不透明相同。
- 户外氛围下给主角衣服补色，不能用 `propAlbedo(atmo) ÷ propAlbedo(morning)` 的比值：propAlbedo 的参考受光含 LampField（早晨 lampGain 0.6），户外没有那么多灯光，比值补不够（阴天校服 s 0.53、l 0.17，裤子 l 0.13）。改用 WP4 户外 kit 的 `Tone.of(atmo).albedo(palette, normal)`，参考朝向取追尾镜头最常看到的背与背顶 (0, √½, √½)；'side' 参考在黎明会把朝上的面补成 l 0.75 的亮蓝。
- 静场替身的根：history 来源的倒影在静场里，根高度是脚本姿势自带的抬升（站立约 0.5 m），不能和 x、z 一起归零，否则镜中的「我」比主角矮半米、脚陷进地里。attachBehind 的宿主是静场替身时，宿主的 box.matrix 已经含锚点，不能再加地面高度（3-10 曾被抬高 2.4 m：静场快照的 floorY 是前面各段累计的高度，Node 测试里要用 `seg.floorY(seg.s0)`，用 0 测不出来）。
- 墙镜替身离玻璃越近，越容易被镜前的东西挡住：洗手台台面 0.87 m、外沿 x = −1.35 时，0.6 m 高的倒影的头要离玻璃 ≥ 1.2 m，视线才从台面上方过去（反直觉：评审建议「挪近一点」反而更挡）。深度改成 0.3 + 0.75 × 玩家到墙的距离；「转头看镜子」改成原地转头 + 朝镜子横移，而不是绕玩家转（绕着转会把镜头甩到离镜子更远的一侧）。
- 镜像替身的手势按「反射之前」写：车窗在主角左边，反射之前替身要用左手（−x）敲玻璃、头往左转；以前写成右手，反射之后手和脸都背对玻璃。反射之前的替身离玻璃 d、手伸到 d − 指长处，指尖就正好贴在玻璃上（Node 里量骨骼 9–11 的顶点 x）。
- 静场替身挂在 set 给的 `at` 上时，朝向按 set 决定（STILL_DOUBLE_YAW）：水里站着的「我」面朝镜头（π），食堂窗里的「我」反射前面朝玻璃（π/2，反射后正面朝窗外的镜头），公交车窗里的照常朝前（0）。
- 构图先在 Node 里算：tests/unit/actors/scene.ts 把 PlayerActor、反光面、替身、影子、CameraRig 按 ViewSystem 的 order 串起来，按章节数据的时刻发 cue（静场 playStill、停拍 playStop、跑段 playRun），再用软件光栅化的主角深度图判断替身的头是否被挡。比开浏览器快两个数量级，浏览器只用来确认。
- `#include <opaque_fragment>` 之前改 `outgoingLight` 可以做局部自发光（替身的眼睛按顶点色找片元）；顶点色是线性值，比较阈值取 0.003 左右，不要和别的深色衣物撞色。

## 修复轮 U5 第二轮（2026-10-01）

- 「在画面里」不等于「看得见」：替身的手、头的 NDC 在 ±1 以内，照样可能整个藏在宿主的头、肩或替身自己的身体后面（3-10 搭肩的手 0 % 可见）。构图测试要用遮挡深度图：`scene.ts` 的 `occluderDepth`（主角 + 任意替身，可跳过替身自己的某些骨骼）+ `visibleAgainst`；截图清单里用同样思路的页面内版本（`U5.vis`：投影三角形 + 重心插值深度），要求 ≥ 50 % 可见。
- 第三只手的手势用时要按演出窗口算：3-10 的搭肩只有 10.8–11.6 s 这 0.8 s，缺省 1.2 s 的伸出到黑场时还在半路。目标点也要选「镜头那一侧的肩头、肩前面」，不能是上臂关节本身（在宿主身体里面）。手势开始时按反射之后的世界坐标判断哪个肩离镜头近，之后不换。
- 「碰到」要量网格：指尖 = 第三只手掌骨上离 arm3Upper 最远的顶点，额头 = 主角头骨上的顶点，距离 < 0.1 m 且 > 5 mm（不戳进头里）。forehead 手势的目标是额头表面，手腕停在它前面一个手长（HAND3_LEN），以前手腕对准头心，指尖不是够不着就是戳进去。
- 俯看水里的倒影：倒影是倒立的，镜头越陡、离替身越近，越先看到鞋底，头藏在肩膀后面。4-6 改成斜着看（约 −36°）、替身放远（离他约 2.65 m），头和眼睛在画面中间偏下。
- 上半身淡出只在镜头还在主角身后时有用：CameraRig 每帧写 `WP5.chaseCam`（停拍看替身、穿玻璃侧拍、回头 / 转头超过 10°、摔倒时为 false），Actor 按它决定。量过：竖屏追尾和 5-3 段内追尾机位不淡出时分别 255 / 335、18 / 18 个障碍不合格，所以这两种机位保留淡出（occlusion.test.ts 三种机位都查）。
- 投影影子要「连着脚」：趴下的影子把根挪到 2.3 m 外，看起来和人断开。改为脚放在你脚前 0.1 m，再以你的脚为中心沿光线方向拉长（投影矩阵右乘一个只拉长水平某一方向的矩阵：先拉长、再投影），手伸到 3.9 m，站立机位看得见。
- 不开浏览器判断「黑板有没有被挡」：在 Node 里 `set.build(ctx)` 出 set 的网格，放到 STILL_ORIGIN，用 three 的 Raycaster 从相机射向黑板上的采样点（SkinnedMesh 也能射，按骨骼变换）。2-9 用它挑出镜头位置：实验台放回主角身旁（x = 1.05），镜头改到他左后方的低处。
- vitest 绝不能 `--root /` 或指向 worktree 外的目录（会扫整个文件系统，Node 涨到 11 GB，整个会话 OOM 被杀）。worktree 外写的临时测试先复制到 `tests/unit/<包>/tmp-*.test.ts`，导入改成相对路径，再 `npx vitest run <该文件>`；提交前删掉。vitest 5 不打印通过用例的 console.log，探针要把结果放进一个必然失败的 `expect(...).toBe('')` 里读。

## 修复轮 U5 第三轮（2026-10-01）

- 渲染端把脚本姿势「留得比 cue 久」时，要写清楚留到哪个事件为止，并在那个事件发生时放下。2-10 的 palmToGlass 曾经一直贴到停拍结束：镜头回到追尾之后，从背后看跪直的他就像站在镜子前（第一到三章不能站）。现在只在第三只手还伸向额头时（`WP5.foreheadReach`）才留，doubleEnd 撤掉手的那一刻直接放下。镜头在同一帧从侧面机位切回追尾，所以姿势跳变藏在切镜头里，也不用把渲染端的前移距离往回滑。
- 跨系统的「留着」条件按 cue 到达时写进共享状态，不要读上一帧画面算出来的值（例如 `WP5.focus.through`）。无头测试 step(n) 跳着推进时，上一帧可能是很久以前的，会让姿势在留和放之间来回闪。
- 跪直、手举过头这类姿势，要在实际机位下检查轮廓：侧面看是跪，从背后的追尾机位看两条小腿竖直，就是站。Node 测试量骨盆和头离地的高度（爬姿 0.33 / 0.48 m，跪直 0.62 / 1.19 m）。
- 端墙镜的 doubleEnd 不应该留下一面空的黑镜子（「再睁开时，镜子里只有我自己」）。history 来源的端墙替身在 doubleEnd 时变回普通倒影：撤掉第三只手、延迟、低头，不淡出，也不当镜头焦点。停拍里保持真正的镜像（`WP5.palmGlass` = 1），否则按「压缩深度」放的倒影，爬姿的手会从镜面里伸出来（深度 0.5 m，手伸 0.74 m）。
- 「眼睛发亮」不能用一个中等的自发光灰：outgoingLight 换成 0.35 线性，经过 Neutral 和 sRGB 以后是 #979797，比 dreamGray 下浅色的脸（#a89f93）还暗，2 px 的眼睛直接被抹掉了。先用 `screenColorBasic`（自发光）和 `screenColor`（脸的反照率 × 受光）在 Node 里比较 HSL 亮度，模型和截图取色的误差在 0.01 以内。眼睛要在顶点着色器里放大：在 `begin_vertex` 之后、蒙皮之前，按静止姿势里眼睛方块的中心缩放（刚性蒙皮下所有顶点都跟头骨走）。
- 页面内取色要读默认帧缓冲：`renderer.render(scene, camera)` 之后，在同一个任务里马上 `gl.readPixels`，这时浏览器还没合成，读到的就是色调映射和 sRGB 之后的屏幕颜色。渲染到 WebGLRenderTarget 再读，是线性的，也没有色调映射（three r186 只在画到屏幕时做 toneMapping），不能拿来和截图比亮度。
- 站在镜子里的人前后约有 0.34 m 厚（脚尖到后背）。镜底、替身离玻璃的距离要能装下整个人，否则脚尖会穿出玻璃，从站立机位看，脚就落到镜面下沿以下。镜子加一块底板（玻璃下沿到镜底），镜面的视觉下沿就成了玻璃线。
- 探针测试不一定要靠一个必然失败的 expect 才能读到结果。`writeFileSync` 把 JSON 写到 scratchpad，测试照常通过，输出可以直接 diff。
- （修复轮 B3）静场里的 `camera` cue 只认 `SET_SHOTS` 的话，跑段机位（turnBack）会被悄悄丢掉。静场回头不能对注视点插值：前后两个注视点的连线穿过镜头，朝向会在中途翻转；按指定方向（左 / 右）对水平朝向插值，俯仰、注视距离、位置线性插值。回头机位要放在主角整个身体的后面（站在洗手台前的人脚跟在锚点后 0.36 m），否则转过去以后他的腿在画面下沿；用「主角落在画面里的顶点数 = 0」检查，不要用 NDC 包围盒（贴近镜头平面的顶点会投影到几百之外，盒子横跨画面）。
- （修复轮 B3）页面里拿镜头：View 把相机加进了场景，`__game.ext.wp5Scene().children.find((o) => o.isCamera)`；`new (cam.position.constructor)()` 就是 three 的 Vector3，可以直接 `project(cam)`。
