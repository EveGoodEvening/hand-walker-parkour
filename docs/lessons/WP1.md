# WP1 Lessons

只追加（OWNERS.json APPEND）。记录可复用的经验：库版本、踩过的坑、被纠正的做法。lead 集成时汇总到 AGENTS.md。


- 步态（`sim/Gait.ts`）跨整数拍的判定两头必须用同一个容差：`cross()` 里 `b <= beat + 1e-9` 让「差 1e-9 就到整数」的拍在这一 tick 落掌，下一 tick 的起点就得是 `floor(prevBeat + 1e-9) + 1`。CORE 版本用 `floor(prevBeat) + 1`，4.8 掌/s 时 288 拍发出 466 次掌根（重复的掌根还会吃掉「干脆」标记）。测试：每拍恰好一次掌根。
- 浮点边界：`0.55 − 0.43 = 0.12000000000000005`，所以「竖直穿透 ≤ 0.12 m 只算绊」必须写成 `pen > grazeY + 1e-9`。凡是规格里写了「≤ / ≥ 某值」的边界，都用精确边界值写一条单元测试。
- 模拟里输入在本 tick 推进之前处理：此刻 `segBeat()` 对应的是 `this.t − TICK_DT`，不是 `this.t`。拿它预测「下一次掌根」要减一个 tick，否则干脆窗口整体偏 8.3 ms。
- 求解器的去重键：只要速度可能因为选择不同而分叉（腿自主抬起时 ×0.85），同一层的节点里程就不同，键里必须带里程；但按 1 mm 取整会让分支永不合并（一个 96 拍的段 87 万节点），按 0.2 m 分桶（节点自身状态仍然精确，只丢掉近似重复的分支）降到 18 万。「让一下」的让开时刻过了之后只记「让开了」，否则每个开口时刻都是一条永不合并的分支。
- 求解器每个节点都要复制一份 `PlayerState`：`Object.assign(new PlayerState(), p)` 占了三成时间，手写 `copyFrom()` 快一倍多；配一条单元测试核对 `copyFrom` 覆盖了全部字段（新加字段忘了写会失败）。热循环里也别每 tick 建闭包：tsx / esbuild 的 keepNames 会给每个闭包调一次 `__name`。
- 检查点之后的 Pace：减速、停拍是临时的，从检查点开始不补放；段中换挡（cadence，5-3「我开始跑」）是持续的，必须按终态补上，否则从换挡之后的检查点重来会回到旧步频。
- 站立段的按步事件（`StepEventDef`，只有 `atStep` 没有 `at`）不进 `CompiledSegment.events`，Sim 直接读 `def.events`；跳过静场时要把还没到的按步事件一起补发，否则必备节拍会丢。
- 跨包的数据问题（例如 §10.1 指派给 WP2 的第一章 R6 间隔）不要为了自己的分支全绿而放松规则：在校验器里加**精确匹配消息**的豁免，降为带说明的 warning，数据一变就自动失效，lead 集成时删除。
- vitest 只按文件并行，同一文件里的用例串行。五章 × 20 个种子的 perfect 扫描按章拆成 `perfect-ch1.test.ts … perfect-ch5.test.ts`，章节还是 null 时只有一个 skip 的用例。测试工具里别用 `until(() => d.of('chapter:end').length)` 这种每 tick 扫全部事件的条件（O(n²)），用 `sim.isEnded`。
- 无头 e2e 很快：`?test=1` 下只在截图帧渲染，第一章 128 s 的游戏时间 1 s 跑完（SwiftShader、640×360、低画质）；渲染每 60 tick 一帧也只要 1–2 s。所以 e2e:chapters 一次取锁跑完五章，远在 10 min 以内。`renderer.info.memory` 只统计上传过 GPU 的几何体，第一遍会随新 chunk 第一次可见而增长；判断泄漏要同一章跑两遍比较第二遍。
- `tsx` 运行 `.mjs` 脚本时可以直接 `import '../src/…/x.ts'`（带扩展名），bot-difficulty 就这样在 Node 里跑模拟，不需要额外的 .ts 入口。
- human 机器人的标定参考（合成的密集跑段，5.4 掌/s、约 50 s、稳度 3、behind）：必需动作 1.3 / 1.7 / 2.0 / 2.5 次每 10 拍 → 失败率约 0% / 3% / 10% / 20%，平均受击 2.5–2.9 次。与 §2.8 的「密度 → 目标失败率」量级一致；第一章的检查点区间在 0%（前四段是 hidden，不会失败）。集成时用 `npm run bot:difficulty -- --trials 60` 看每个区间，超标的区间在报告的 `over` 里。
- 滚动视野的重新规划（机器人每 45 m 续一次）不要在按着 ↓ 的时候做：续规划前要松开 ↓（求解器假定起点没有按键），长桌底下一松手就会撞。等 ↓ 松开再续。
