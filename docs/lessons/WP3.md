# WP3 Lessons

只追加（OWNERS.json APPEND）。记录可复用的经验：库版本、踩过的坑、被纠正的做法。lead 集成时汇总到 AGENTS.md。


- 2026-09-30 | 截图卡死：读章时任何异常都会让 `Game.boot` 失败，`__game.ready` 永远不 resolve，`shot.mjs` 就一直等下去并占着浏览器槽位（没有超时）。跑截图一律 `timeout -k 10 300 node scripts/shot.mjs …`；kit 的 `build` 出错要兜底（WP3 的 ChunkStreamer 用 `safeBuild`：记日志、改用 CORE 占位 kit）。先在 Node 里用 tsx 把每个 kit 变体 build 一遍再开浏览器，能省掉大部分这类问题。
- 2026-09-30 | three r186 的 `renderer.info.memory.geometries` 在几何体**第一次被画**时才加一，不是创建时。要做到「读章完成后几何体数不变」，读章后必须预热：`renderer.initTexture` 上传全部纹理，再把整个场景临时设 `visible = true`、`frustumCulled = false`，在 1×1 视口里画一遍，然后恢复（WP3 的 `View.warmUp`）。之后别的包如果在游戏过程中才创建对象，计数还是会变。
- 2026-09-30 | 灯光数量变化会让所有材质重编译（程序缓存键里有光源数）。没有平行光的氛围预设也要保留那盏 `DirectionalLight`，只把强度设为 0，别切 `visible`。
- 2026-09-30 | 几何累积器里用负缩放（镜像）矩阵时，三角形绕向会反，正面朝里被剔除。`KitGeo.withMatrix` 按矩阵行列式自动翻转绕向；镜中房间里的镜像桌椅就是这样画的。
- 2026-09-30 | `PAL` 用了 `as const`，函数默认参数写 `wall = PAL.wall` 会被推成字面量类型，传别的颜色就报错。默认参数要写成 `wall: number = PAL.wall`（与 CORE lessons 里 TUNING 的坑相同）。
- 2026-09-30 | JS 的 `%` 对负数得负数：按 x 坐标从数组里取颜色时 `arr[(n % 4)]` 在左半边会取到 undefined，要写 `((n % 4) + 4) % 4`。
- 2026-09-30 | 一次 draw call 里同时做「加亮」和「压暗」的贴花：混合用预乘 alpha（`CustomBlending`，`ONE` / `ONE_MINUS_SRC_ALPHA`）；亮的贴花输出 `(rgb, 0)` 等于加法，暗斑输出 `(0, a)` 等于按 a 压暗。
- 2026-09-30 | 光滑地面上灯管的倒影：真实反射点在镜头前 `d·h镜/(h镜+h灯)` ≈ 0.23 d 处（镜头 0.92 m、灯 3 m），在低机位下几乎全被主角挡住。改成放在 0.45 d 处、沿 s 拉长，「水银河」才看得见。窗的倒影用柔光椭圆，别用尖头的条，否则像地上画的箭头。
- 2026-09-30 | 地面贴花 / 湿痕这类「覆盖在地面上的第二层」要用与地面相同的顶点色做边缘（`floorBlob` 的 rim 参数），不然边缘比地面亮，看上去是一块块浅色贴纸。
- 2026-09-30 | 截图验证亮度：在页面里 `renderer.render` 之后立刻 `gl.readPixels`（同一个任务里），不需要 `preserveDrawingBuffer`。WP3 的调试扩展 `__game.ext.wp3Luma(x0,y0,x1,y1)` 返回区域的平均 / p99 / 最大亮度。
- 2026-09-30 | 无头 Chromium 里 canvas 中文能正常出字（本机有文泉驿正黑）：黑板字「你为什么不站起来？」截图可读。
- 2026-09-30 | LampField 的 R 通道存「亮度 ÷ 2」（UNORM8 只能存 0..1，管灯叠加后会超过 1），着色器里乘回 2；G 通道存灯自身的电平，发光体用它明灭，这样灯管自己灭了而邻灯的余光还在时，灯管不会还亮着 40%。
- 2026-09-30 | 早晨的日光（半球 1.2 + 平行光 1.6）远强于灯（增益 0.6），灯全灭时画面平均亮度只降约 20%；夜里（nightIndoor）降约 73%。「灯亮 / 灯灭相差 ≥ 30%」要在夜间场景里测。
- 2026-09-30 | 水磨石纹理按设计是 256 px/m 下石子半径 0.6–3.5 px，覆盖率约 50%；低机位（静场 0.3 m 高）贴近看会像碎石。石子颜色朝底色混 40%、不透明度 0.75 以后才像打磨过的水磨石。
- 2026-09-30 | 低画质（像素比 0.6、无抗锯齿）下，墙根、隔间后墙与地面的 T 形接缝会漏出一个个背景色的亮点。贴地的墙面往地面以下多伸 6 cm、相邻面彼此多搭 5 cm 就没有了（地面本来就不写深度，多出来的部分看不见）。
- 2026-09-30 | 家具「浮」在地上的感觉，用画进 floor 几何体的柔边暗矩形（`contactShadow`：中心暗、外圈渐变到地面顶点色、同一张地面纹理）就能压住，零额外 draw call；要把它夹在本 chunk 的 z 范围里，否则越界的部分会被下一个 chunk 的地面盖掉，留下硬边。
- 2026-10-01 | 画质切换（含自动档位在游玩 3 s 后那一次）不能「重来一遍」：以前 `setQuality` 调 `atmo.snap` 又整个重建世界，灯的熄灭 / 闪烁 / 声控、fog cue、进行中的氛围过渡、跑段黑板全被清掉。现在 LampField 重建灯表时按（种类、s、x）迁移每盏灯的状态（读章 `clear()` 之后不迁移），闪烁种子也只由这三项决定；氛围状态里存未乘 fogMul 的 `farRaw`，切画质只重算 far；黑板只在读章时建。任何「读章之后还会调用」的重建路径都要先问：运行状态存在哪、会不会被一起扔掉。
- 2026-10-01 | §5.1 色板是「画面上看到的颜色」，不是反照率。r186 的 Lambert 对半球光、平行光都要除以 π，侧墙只吃到半球光的一半；NeutralToneMapping 的 toe 先从各通道减去约 0.04，暗部饱和度被抬高。直接拿 #5F7F7A 当墙裙顶点色，早晨截图里是 #183E3C（饱和度 0.4）。`src/render/wallTone.ts` 按早晨走廊侧墙的参考受光反推反照率（线性，可 > 1，KitGeo 的顶点色接受线性 RGB）；夜景 lift 0.3 并去饱和，否则灯管增益 1.4 会把墙照得发白。先在 Node 里写一个「Lambert ÷ π + LampField + Neutral 色调映射 + sRGB」的小模拟器对色，再上浏览器验证，比反复截图快得多（模拟值与截图取色差 1–2 个色阶）。
- 2026-10-01 | 截图清单里的数值验收要「自带断言」：在同一页里先量、再切对照条件、再量，条件不满足就在 eval 里 `throw`（shot.mjs 会记为失败、退出码非 0）。分两张截图各量一次再人工比，很容易量错对照（以前 `wp3Atmo` 只 snap 不 apply，`wp3Luma` 又不走 frame，对照组量到的其实是早晨的光）。
- 2026-10-01 | 本机的 PreToolUse 钩子要求浏览器命令走 `~/.claude/bin/heavy-gate -l '<标签>' -- <命令>`，并且用后台方式运行（不能包 `timeout`）；等结果用 `until grep -q … log; do sleep 2; done` 的后台命令，不要前台 `sleep`。shot.mjs 开头会在 dist 过期时重新构建：构建期间别改 src，否则构建可能读到改了一半的文件。
