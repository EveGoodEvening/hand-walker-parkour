## 2026-09-30

- **原文核对**：`src/levels/sourceQuotes.ts` 由 `node tests/unit/content/tools/gen-source.mjs <小说目录> src/levels/sourceQuotes.ts` 生成（逐行 JSON 字符串，join 后与原文件逐字节一致，头注释里有 sha256）。`tests/unit/content/quotes.test.ts` 对每条 `quote: true` 做子串检查。第四章原文用中文引号“”，其余四章用 ASCII 双引号；台词一律不带引号存（界面按样式加）。句中片段（如「水洼里的影子没有抬。」「它是反的。」「它比我快。」）是原文的连续片段，可以直接用。
- **原文不进产物**：`tests/unit/content/isolation.test.ts` 从 `src/main.ts` 沿 import（含 `import.meta.glob`）走依赖图，断言 `sourceQuotes.ts`、`lint.ts` 不可达；`lint.ts` 自己也不 import 原文（由调用方传入）。构建后用 `node tests/unit/content/tools/leak-check.mjs` 检查 `dist/index.html`：原文每个 25 字窗口都不应命中（lines 每行 ≤ 24 字）。
- **R6（20 s 一个主异常）按事件计数**：每个 `doubleMod`、非 normal/blob 的 `shadow`、`memory`、`board`、以及追随者从 hidden/absent 变成别的模式的 `follower` 事件都算一次；`double` 不算；段定义里的 `follower`（段切换）也不算。同一个异常的连续演出要写成一个事件（组合 doubleMod），否则 1–3 s 内会被算成好几个。回头窗口里的异常要同时满足「窗口开始 vs 前一个异常」和「窗口结束 vs 下一个异常」两个 20 s。静场里的异常校验器不查（2-9、3-10、4-3 按设计本来就在一个场景里连着出现）。
- **修第一章时不要改段长**：`tests/unit/core/levels.test.ts`（CORE，WP 不能改）断言第一章全长 518 拍。能动的是窗口、停拍位置和停拍 timeline。
- **CORE 求解器的伏低只有 2 拍**（按住选项 1–13 tick，松手后按 `duck.minBeats` 收）：进深 1.2 m 的 `labBench`、`len ≥ 2` 的长桌在 CORE 校验器下无解。实验台用 `[beat, 'HHH', 0.8]`（len 单位是拍）。
- **R8 与 R7 的坑**：求解器从每个段首和检查点的中道出发，段首 / 检查点 1.6 s 内不能要求动作，所以前两行别放在中道。新类别第一次出现要在「按静态 s0 算的接触时刻」前 ≥ 1.2 s 有提示：移动障碍（walk）按生成位置算，提示要更早。每章都要重新给 jump / lane / duck 提示（校验器按章记），即使玩家已经看过。
- **R7 新种类与种子**：`KIT_SYMBOLS` 的轮换起点由种子决定，`'B.B'` 这种两格同符号的行一定是两个不同种类。想让「新种类第一次出现时这一行只有它」对所有种子都成立，早期的行写显式种类（`['cart', '.', 'cart']`）。`tests/unit/content/chapters.test.ts` 用种子 1–20 加章节种子检查。
- **加密谱面的办法**：先算出每段的休息窗（文字 −0.4/+0.8 s、主异常 −1/+2 s、检查点 +1.6 s、段末 −0.8 s、回头窗口到 then + 0.8 s），在休息窗外按 3.5–4 拍补行，再用 `validateChapter` 反复验证、删掉被点名的行；休息窗里可以放只占边道的「被动」行（玩家待在中道不用动）。纸条所在车道前后 2 拍要留空，否则自动驾驶够不着。
- **浏览器**：`node scripts/e2e-smoke.mjs --ch chN`（或 `node scripts/e2e-chapters.mjs`）能跑任意章，必备节拍取自 `__game.ext.requiredBeats`；五章各 2–3 s 墙钟。ch4 缺 `fingerPractice`（结尾卡输入，Game 还不支持），ch5 缺 `seventhFall` / `theyPractice`（站立段的 atStep 事件，WP1 Stand），其余全部触发、0 摔倒。
- **移动障碍会穿模**：`walk` 的位移是 `speed × tSeg`（从段首算起），段里越晚被追上的人走得越远。用名义时间算出追上的位置，保证它被追上前约 6 s 的路径上同车道没有静止障碍（`tests/unit/content/chapters.test.ts` 的「画面上不穿模」）；同向爬行者要放在早一点的拍上，不然会一路穿过别的障碍，甚至到段末都追不上。

## 2026-10-01

- **A-11 要按 Sim 时间轴、连同静场一起数**：校验器的 R6 只看跑段，静场里的主异常和跨段的间隔它不查。用 `tests/unit/content/anomalyTimeline.ts`（perfect 自动驾驶跑整章，按实际触发时刻收集）检查。静场里的异常到下一个异常的间隔，要把静场剩下的秒数一起算上（2-5 的第三只手在 5.0 s，静场还剩 6 s）。
- **每拉开一次 20 s 都要花全章时长**：两个主异常之间至少 20 s，数据只能靠加长中间的跑段来满足。动手之前先算全章合计会不会超过 §4.6 的 +15%（第二章修完 A-11 一度到 205 s，上限 201 s），超了就得从没有异常的段里缩（2-2、2-8 的尾部）。
- **站立段不能声明 NPC 组**：crowd 只能引用紧挨着的前一个跑段的组 id（4-3 → 4-2 的 `ring2` / `imitators`），不要引用更早的段。
- **静场 / 站立段等输入时时钟暂停**（`StillRunner`）：`duration` 只算不等输入的部分；最后一句文字触发之后还要留出显示时间（字数 × 90 ms + 800 ms），否则段会在字显示完之前结束（5-8 从 11 s 改成 13 s）。

## 2026-10-01（验收第 2 轮）

- **为了时间加长的段落要保持稀疏**：A-11 逼着 2-10 从 40 拍加长到 140 拍，加长的部分只能放边道的被动行，不能复制前面的障碍块。§2.8 要求最后一个跑段是减速收束，技巧高潮在倒数第二或第三个跑段（第四、五章按表格点名 4-5、5-3）。`chapters.test.ts`「§2.8 难度曲线」用三把尺子比：行密度、20 拍峰值、求解器最少输入次数 / 10 拍（要先去掉纸条）。
- **墙上的东西要放在「那一刻」的前方足够远**：跑段镜头在玩家身后 2.35 m（横屏）或 3.8 m（竖屏）。左墙离右道玩家的镜头约 2.5 m，横屏要在镜头前约 3.3 m 才在画面里，竖屏（9:20）要约 6.5 m。门牌、涂鸦这类要在某一拍被看见的墙面，至少要放在玩家前方 7 拍左右。
- **`hush` 的拍数按触发时的步频换成秒**：放在停拍 timeline 里时，玩家要从 0 加速，实际走过的拍数比写的少，要多写 2 拍左右。
- **段末的减速要让段在减速里结束**：`slow` 在段末之前就结束的话，淡黑时玩家又在加速。按「减速开始 + 秒数」晚于段末来放。

## 2026-10-01（评审修复 U1）

- **§2.8 的「必需动作密度」按求解器最少输入算，不按行数**：只占边道的行对中道的玩家是被动的，一段可以有 1.4 行 / 10 拍却 30 s 不用按键（2-10、2-7、5-6）。加密时给每个乐句放一个中道部件，用 `solver.solve(seg, { noAsk: true })` 和带 `minGap` 的两种算法都量一遍（两者可能差一次：3-6 是 15 对 16），`chapters.test.ts` 用的是不带 `minGap` 的那个。量「最长多久不用按键」时，停拍算在里面，剧本慢行（`slow`）不算；快照里的 `player.cadence` 会跟着 `slow` 变，名义速度要用编译段的 `cadenceAt(segBeat) × stride`。
- **慢速楼梯上的撑跃**：滞空 `clamp(3 / 步频, 0.48, 0.72)`，步频 ≤ 4.17 时一律 0.72 s。高于障碍顶的那段水平距离 = 0.72 × √(1 − 4h / 2.4) × 速度，要大于碰撞盒 0.5 m + 障碍进深。步幅 0.6、3.0 掌/s（1.8 m/s）时，0.35 m 的拖把桶任何时刻都跳不过，0.28 m 的书包只有约 ±40 ms；书 / 报纸堆要 ≥ 3.6 掌/s 才有 ≥ 0.16 s 的单车道窗口。楼梯上要放低矮障碍先算这个，跳不过的改成横档（`mopAcross`）。
- **评审的 jumpall 探针会被截断**：它从障碍前 5 拍、中道起步，只在之后 0.25–1.5 s 里试起跳。2-1 @39 起步正好撞上同向走的腿（@22，1.2 m/s），绊一下把窗口推到采样范围外面，量出 0.1 s，实际 0.225 s（`KMAX=300` 再量）。看到窗口贴着采样上沿时先查是不是探针本身撞了别的东西。
- **`tests/unit/core/levels.test.ts`（归 CORE / U4）断言 1-2 两侧储物柜的长度都是 14 拍**：要给陈默留出让开的地方，把右侧柜子错开（@99–@113），不要缩短它。改数据前先 `grep -rn` 一遍别的包的测试里有没有写死章节数据的断言。
- **字幕是滚动的两行**：一个两行事件之后再推一行，最旧的一行被挤上去、挤掉。原文一句太长时拆成「两行事件 + 下一个单行事件」按原文顺序滚出来，不要把不相邻的两句塞进一个事件（附录 A-8；`lint.ts` 的 `lintSplices` 现在会报 `A-8-splice`）。半句比喻要补成原文整句时，用「新的前半句 + 原来的 LineId」做两行事件，原来那条台词的 id 和文字不动（`tests/unit/ui/ui.test.ts` 按文字断言了 `c1.oldFriend`）。
- **时长预算已经贴着上限**：第二章合计 200.9 s（§4.6 的 +14.8%，上限 +15%），第五章非跑动 24.6%（上限 25%）。给静场加字之前先算：静场 ≤ 15 s 不含等输入，文字要在段末之前显示完（字数 × 90 ms + 800 ms），超出的时间要从同章没有主异常约束的静场里挤（2-3 取餐 8 → 7.3 s、5-1 7.5 → 6.4 s 都是删掉字幕显示完之后的空白）。
- **human 机器人 60 次的失败率噪声约 ±3.5 个百分点**：比较两个区间谁更难（3-6@0 与 3-4@0），用 `--trials 200` 再看一遍；60 次时 3-4@0 是 8.3%，200 次时只有 4.5%。
- **同向爬行的人从段首开始走**（位移 = 速度 × 段内时间）：改了一段的步幅或步频（4-5），要按新的时间轴反推它们的起点（s₀ = s(追上的拍) − 速度 × t(追上的拍)），否则追上的位置会漂几十拍，穿过别的障碍。
